| Accept: accepts the current position and saves the changes you have made <br>Once you are happy with the current position use Accept to save it and finish positioning.<br> <br>Before it saves the position PRIMER checks all the nodes at (ls-dyna) joints in the mechanism to check that positioning has not pulled them apart. It applies a twin tolerance:<br> <ul> <li>An absolute value of 1.0e-3. This is the value hard-wired into the Ansys LS-DYNA keyword reader. </li> <li>A distance of 1.0e-6 times the model longest diagonal </li> </ul> <br>Any joints at which separation of nodal pairs exceeds this figure will be listed and you will be given the option of Autofixing them.<br> <br>This is performed by moving each pair of nodes to their average position and, so long as the errors are small, this is an acceptable distortion of the model. This is an iterative process since if a node is on more than one joint then correcting for joint A may move it out of position for joint B. If there are still errors after 5 passes the operation is abandoned and it is left to the user to sort out.<br> <br><br>  Warning: Avoid repeated [Position, Accept, Autofix] cycles on a model <br><br>>  <br>> This is because each Autofix operation changes the geometry of your mechanism slightly, and while a single such change may be insignificant repeated use of this feature will build up cumulative errors. In particular repeated Autofixing of joints, which moves pairs of nodes to their average coordinate, may introduce alignment errors.<br>>  <br>> It is better to achieve a position in a single operation from an unmodified mechanism model. If you are planning to generate a series of positions in succession you should use [Model, Copy](model-copy-copying-models-internally.md#MODELCOPY)to create a new model from an original one each time, and create the position in the copy.<br>> |

#####  Reject: rejects the current position, restores the initial one and exits the positioner

Use Reject if you want to abandon positioning and restore the initial position. All changes made during positioning will be lost, and you will return to the main [Position](position-analysing-mechanisms.md#operations)menu with the model unchanged.

#####  Reset all: restores the intial position.

Sometimes positioning goes horribly wrong and the best thing is to start again. Reset all restores the initial position that was saved when you entered the positioner, cancelling all changes made since then. You can use this at any time.

| Global Accuracy: sets the precision of the mechanism calculation  <br>By default the precision with which the mechanism positioning process calculation is performed is based on the diagonal of the box bounding the mechanism times a "convergence factor" of 1.0e-4. Therefore a mechanism fitting into a box with a diagonal of one metre will be solved to a precision of approximately 0.1mm, this being the maximum permitted error at mechanism connection points.<br> <br>This error manifests itself as small differences in the coordinates of theoretically coincident connection points on assemblies A and B that are joined by a mechanism connection. As part of "accepting" a mechanism PRIMER checks for Ansys LS-DYNA joints ( \*CONSTRAINED\_JOINT ) at such points and moves points A and B to an identical average position so as not to exceed the joint coincidence tolerance permitted by Ansys LS-DYNA. Points not connected by an Ansys LS-DYNA joint are left in their slightly different positions.<br> <br>Therefore the result of mechanism positioning is a series of small distortions of your model, and possibly also small changes to joint geometry. You must make an engineering decision about what constitutes an acceptable tolerance for your particular model, and you may wish to use Global accuracy to make mechanism positioning more precise. It will not usually be sensible to make it less precise than the default value of 1.0, although doing so will make dragging faster - possibly an acceptable setting for performing an interactive demonstration in front of an impatient audience!<br> <br>Detailed convergence parameters can be set in [Options](options-0.md#options), described below, but these are rather opaque and a simpler value to use is the Global accuracy parameter which can be in the range 0.1 to 100.0, default 1.0.<br> <br>The effect of this factor is to divide the default value of the following three convergence parameters thus:<br> <br><br>| Convergence factor | = | 1.0e-4 / Global Accuracy |<br>| --- | --- | --- |<br>| End movement factor | = | 1.0e-8 / Global Accuracy |<br>| Step size factor | = | 1.0e-4 / Global Accuracy |<br><br> <br>You can still set these individually in [Options](options-0.md#options)below, this is just a simpler and easier way of doing that. |
| --- |
| Global Accuracy is a floating point number that may have any value in the range 0.1 to 100.0, and typical values are:<br> <br><br>| Global Accuracy typical values and their meanings. |<br>| --- |<br>| 0.1 | Very loose tolerance,  ***not recommended*** |<br>| 1.0 | **Default value** , suitable for dragging with the mouse |<br>| 10.0 | Tighter value, practical limit for dragging with the mouse |<br>| 20.0 | Tighter still, suitable for "specified" motion |<br>| 50.0 | Very tight, practical limit for "specified" motion |<br>| 100.0 | Extremely tight: will probably lock up. |<br><br> <br>You can change the value at any time, and some experimenting may be required with very complex mechanisms to find a value that gives a reasonably compromise between precision and speed of positioning.<br> <br>The default value may be changed by the preference:<br> <br>primer\*mechanism\_accuracy:  *value* |
