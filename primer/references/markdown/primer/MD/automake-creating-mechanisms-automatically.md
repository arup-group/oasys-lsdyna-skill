###  Automake: Creating Mechanisms Automatically

As well as creating mechanisms manually PRIMER 11 onwards can calculate mechanisms automatically from the structure of your model.

 ![](../Storage/primer-22-1/primer_links/sect_6/mechanism/fig_7.png)

| How it works  <br>(1) Select an initial "seed" node, the Start node |
| --- |
| ![](../Storage/primer-22-1/primer_links/sect_6/mechanism/fig_7a.png)![](../Storage/primer-22-1/primer_links/sect_6/mechanism/fig_7b.png) |
| In this example, designed to create a mechanism from the front suspension of a vehicle model, the user has picked a node on the front tyre, shown here with a cross. |
| (2) Press Calculate |
| ![](../Storage/primer-22-1/primer_links/sect_6/mechanism/fig_7d.png)![](../Storage/primer-22-1/primer_links/sect_6/mechanism/fig_7c.png) |
| PRIMER will "grow" the first assembly, here the red wheel, outwards from that seed node until no more connected structure can be found, at which point the first assembly has been defined.<br> <br>It then looks for potential connections, in the form of joints (\*CONSTRAINED JOINT) or discrete elements (\*ELEMENT DISCRETE, or \*ELEMENT BEAM type 6) on that assembly.<br> <br>If any are found then the 2nd node on these forms a seed node on a new assembly, and the growth processes is repeated. If a valid assembly can be created then PRIMER uses the joint or discrete element to make a connection. |
| This "grow assembly", "look for connections", "make new assembly on the other side" process is repeated until no more eligible structure can be found, at which point the mechanism is complete. In this example it can be seen that five assemblies have been created: |
| <ul> <li>Initially selected wheel (red) </li> <li>Wishbone (green) </li> <li>Subframe (blue) </li> </ul> |
| During this process PRIMER provides visual feedback by colouring each assembly as it is created, with the rest of the model being made transparent, as shown in the example here. (These are the default settings, to alter them see " [Controlling how things are drawn](Graphics.html#graphics)" below.)<br> <br>You can use  [Position](automake-creating-mechanisms-automatically.md#am_pos) to try out positioning this mechanism, and if you are happy with it you can  [Save](automake-creating-mechanisms-automatically.md#am_save) it in the database.<br> <br>In an ideal world this will produce a mechanism that models exactly what the model will do during the analysis, and sometimes it does, but in most cases you will need to adjust the "growth" procedure to achieve the result you want. The various controls available to you are described below. |

| Once you have used Calculate for the first time the Automake panel will become populated with the details of the mechanism you have created. You can adjust the settings here and repeat the Calculate process as many times as you like until you achieve the results you require. |  |
| --- | --- |
| Assemblies and Connections list what has been created.  <br>![](../Storage/primer-22-1/primer_links/sect_6/mechanism/fig_7h.png)These buttons are colour coded to match the display in the graphics window, and if you hover the mouse over a button the relevant item will be highlighted and labelled graphically, making it easy to identify items.<br> <br>To edit an assembly or connection click on its row button, and this will map the relevant editing panel as shown above. Automatically calculated mechanisms are always "scratch" definitions until they are saved, so you can edit items without fear of affecting any other mechanisms saved in your model. |
| **"Locking" assemblies and connections using**  ![](../Storage/primer-22-1/primer_links/sect_6/mechanism/fig_7f.png)<br> <br>Normally each new Calculate operation will delete all assemblies and connections made previously and restart from scratch, meaning that any edits you have made will be lost. If you want to keep any item during this process then "lock" it using this button, and it will be retained. A locked assembly or connection will show a closed padlock coloured in red, in addition if you lock a connection then it also implicitly locks any assemblies to which it is attached, and their padlock symbols will turn blue to reflect this.<br> <br>**Note** :<br> <ul> <li>&quot;Locking&quot; an assembly in this context does <i> <b>not </b> </i>restrain it in any way during positioning. To do this edit it by clicking on its row, and select the combination of restraints that you require. <br> <br> </li> <li>In the same way &quot;Locking&quot; a connection here does <b> <i>not </i> </b>&quot;clamp together&quot; its assemblies in any way. To do this edit the connection and select the &quot;Locked&quot; button on that panel. </li> </ul> |
| Merge...
  **"Merging" assemblies**<br> <br>Sometimes pieces of structure are split up into more assemblies than necessary, and while it would be possible to adjust the attributes of connections to correct this it is easier just to merge the offending assemblies directly. Merge... does this for you in the following way:<br> <ul> <li>You are given a list of all the assemblies in the current mechanism-to-be. </li> <li>You must select two or more of these </li> <li>All the selected assemblies will be merged into the first one. </li> </ul> <br>The merge process does the following:<br> <ul> <li>All part sets, parts and node sets in assemblies #2 to #n are added to assembly 1. </li> <li>All assemblies #2 to #n are deleted. </li> <li>All connections between a pair of assemblies both in the list #1 to #n are deleted. </li> <li>All connections referencing an assembly #2 to #n has this connection reassigned to #1. </li> <li>Assembly #1 is locked to prevent any later passes deleting and/or modifying it. </li> </ul> |

| Assemble from... controls the items used to create assemblies.  <br>Assembly growth will only occur across the item types selected below. | ![](../Storage/primer-22-1/primer_links/sect_6/mechanism/fig_7i.png) |
| --- | --- |
| | Elem parts . <br>(Solid, shell, beam and thick shell parts) | Will grow via nodal connectivity only for deformable parts, ie growth only occurs across elements connected by common nodes. <br> <br>For rigid parts growth extends to all elements in the part regardless of connectivity. |<br>| --- | --- |<br>| Nodal RBs | Nodal Rigid Bodies grow across all nodes in the body, which add their node set to the assembly. |<br>| RB Extra no | Extra nodes on rigid bodies grow to all such nodes. Their nodes are not added to the assembly since these will be picked up anyway by virtue of the parent part being used. |<br>| RB Merges | Rigid body merges (\*CONSTRAINED RIGID BODIES) grow to the "other" part, either constrained or lead part, including it in the assembly |<br>| More constrained | Maps a sub panel listing other \*CONSTRAINED items that can cause connectivity, for example welds. The relevant parts, nodes or elements get added to the assembly. |<br>| Tied conts | Tied contacts, which includes spotweld contacts, can be used to track across tied nodes. This is off by default since it can result in "too much growth" unless controlled. | |

| **Controlling what is used for assemblies via "Exclusion".**<br> <br>By default all these categories (except tied contacts) are turned on, and hence eligible for assembly growth. However you can turn any category off at two levels:<br> <ol> <li>Turn off the whole category by deselecting its button. </li> <li>Turn off individual coponents within it by using the [ <span class="buttontext">Exc </span>] &quot;exclusion&quot; button. </li> </ol> <br>Exclusion allows you to deselect individual parts, constrained items and contacts so that they do not contribute to growth in a Calculate operation, and this can be used to limit what is considered. | ![](../Storage/primer-22-1/primer_links/sect_6/mechanism/fig_7g.png) |
| --- | --- |
| Selective exclusion can be changed at any time, and used in combination with "locking" of assemblies you might exclude some items, eg contacts, to grow initial assemblies, then lock these and re-enable growth across the excluded items for subsequent Calculate operations. |

| Connect via joints  <br>Controlling which joints make connections | ![](../Storage/primer-22-1/primer_links/sect_6/mechanism/fig_7j.png) |
| --- | --- |

| The folowing subset of joints (\*CONSTRAINED JOINT) types are used to make connections between assemblies<br> <br><br>| **Joint type** | **Mechanism connection type created.** |<br>| --- | --- |<br>| SPHERICAL | [Pin joint](connection-creation-and-editing.md#pin_joint)at the location of N1 |<br>| REVOLUTE | [Hinge joint](connection-creation-and-editing.md#hinge_joint)from N2 to N4 |<br>| CYLINDRICAL | [Line joint](connection-creation-and-editing.md#line_joint)from N2 to N4, no restraint on sliding or rotation |<br>| UNIVERSAL | [Pin joint](connection-creation-and-editing.md#pin_joint)at the location of N1 |<br>| TRANSLATIONAL | [Line joint](connection-creation-and-editing.md#line_joint)from N2 to N4, sliding unlimited but rotation forbidden. |<br>| *Other types* | *Are currently not considered* |<br><br> <br>Exclude... may be used as above to exclude any joint from being eligible to make a connection. |
| --- |

| Connect via Element Discrete  <br>Controlling which discrete elements (springs and dampers defined by \*ELEMENT DISCRETE) make connections. | ![](../Storage/primer-22-1/primer_links/sect_6/mechanism/fig_7k.png) |
| --- | --- |
| "Short" discrete elements, usually springs, are sometimes used to model flexible connections, so this option allows you to make mechanism connections using them.<br> <br><br>| **Discrete element type** | **Length** | **Mechanism type created** |<br>| --- | --- | --- |<br>| 2 noded springs and dampers | &lt;= Shorter <br>than value | [Pin joint](connection-creation-and-editing.md#pin_joint)at average location of N1 and N2 |<br>| 1 noded springs and dampers | n/a | Fully restrained [point](nan)on parent assembly at location of N1 |<br><br> <br>Exclude... may be used as above to exclude any element from being eligible to make a connection. |

| Connect via Element Beam  <br>Controlling which discrete beam elements (\*ELEMENT BEAM using section type ELFORM = 6) make connections. | ![](../Storage/primer-22-1/primer_links/sect_6/mechanism/fig_7k.png) |
| --- | --- |
| "Short" discrete beam elements using section formulation ELFORM = 6, often of zero length, are also often used to make flexible connections between components in a model.<br> <br><br>| **Beam element type** | **Length** | **Mechanism type created** |<br>| --- | --- | --- |<br>| 2 noded beams of element formulation (ELFORM) 6 | &lt;= Shorter <br>than value | [Pin joint](connection-creation-and-editing.md#pin_joint)at average location of N1 and N2 |<br>| *other beam types* | *n/a* | *Are not considered* |<br><br> <br>Exclude... may be used as above to exclude any element from being eligible to make a connection. |

| Controlling how things are drawn  <br>Generally a mechanism forms only a small part of a larger model, and it can sometimes be hard to see what is happening. To try to relieve this problem the Automake function temporarily changes the visual attributes of the plot, breaking the model down into two categories: | ![](../Storage/primer-22-1/primer_links/sect_6/mechanism/fig_7l.png) |
| --- | --- |
| | "Model" | Everything in the model that is  ***not***  in the mechanism <br> <br>By default this is drawn in transparent grey. |<br>| --- | --- |<br>| "Mechanism" | Those parts of the model in the mechanism. <br> <br>By default this is drawn "normally" (ie opaque) in the colours of the various mechanism assemblies. |<br><br> <br>You can change these settings at any time, and the graphics will update immediately. Swap all swaps over all model and mechanism settings, and can be useful when trying to see what is not in the mechanism.<br> <br>When you finally exit from Automake the original model colours and other graphics attributes will be restored automatically. |

| Other commands ![](../Storage/primer-22-1/primer_links/sect_6/mechanism/fig_7m.png) |
| --- |

| Position performing a test mechanism positioning operation.<br> <br>Once you have created some assemblies and connections you can use Position at any time to try positioning them. This will launch the mechanism positioner on you current definition.<br> <br>**Warning** : Within Automake your mechanism is always a "scratch" definition, so anything you do with it will not affect items stored permanently in the database. However an exception to this is that if you perform a positioning operation and then Accept rather than Reject the results any changes you have made to nodal coordinates and rigid body attributes  ***will become permanent***  . |
| --- |
| Reset All resets all settings in the Automake panel.<br> <br>If your mechanism has gone horribly wrong, or you simply want to start again with a new one, then Reset all will reset to default the following:<br> <ul> <li>All existing mechanisms and connections are deleted, whether or not they are &quot;locked&quot;. </li> <li>All exclusion lists for assemblies and connections are deleted. </li> </ul> |
| Save stores your mechanism in the database.<br> <br>If you are happy with your mechanism you can store it permanently in the database with Save . This will also exit from the Automake panel, and restore all model colours and visual attributes. |
| [X] To exit without saving.<br> <br>If you want to abandon Automake without saving your results simply use the [X] button at the top right of the panel. Colours and visual attributes will be restored, but no mechanism data will be saved. |
