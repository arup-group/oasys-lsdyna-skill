###  Sorting Object Menu Contents

| By default object menus are present in M odel/ L abel order, referred to as M/L, meaning
<ul style="font-size: 14.6667px;"> <li>All items in Model #1, sorted into ascending order by item label</li> <li>All items in Model #2, sorted by ditto<br>etc</li>
</ul>
<br>However it is possible to resort object menus dynamically by clicking on the menu title bar, which will cycle the sort process through:<br>
<ul style="font-size: 14.6667px;"> <li>A-Z (alphabetic sorting by item title)</li> <li>Z-A (reverse alphabetic sorting)</li> <li>0-9 (ascending numeric sorting by item label)</li> <li>9-0 (reverse numeric sorting)</li> <li>M/L (default&#160;<span class="courierbold">M</span>odel/&#160;<span class="courierbold">L</span>abel sorting)</li>
</ul>
<br>Further clicks will repeat the cycle above. | ![](../Storage/primer-22-1/primer_links/sect_2/selection/fig_6_2h.png) |
| --- | --- |
| For example in this case sorting by A-Z gives the following. <br>Note that alphabetic sorting has ignored both model id and item label, and considered only titles. Since there are two (very similar) models in this example this has resulted in rows from M1 and M2 being interleaved.<br> <br>Note also that the menu title row has changed to show the current sort method, here showing:<br> <br>(A-Z) PART(s) (all models) | ![](../Storage/primer-22-1/primer_links/sect_2/selection/fig_6_2h1.png) |
| In this example two further clicks have given 0-9 sorting <br>Note again that the model id has been ignored, and sorting is by strict label id regardless of model.<br> <br>Where items in 2 or more models share the same label, for example here P10000, they are shown in ascending model order, but otherwise the model id is ignored.<br> <br>As before the top row of the menu shows the current sort method, now:<br> <br>(0-9) PART(s) (all models) | ![](../Storage/primer-22-1/primer_links/sect_2/selection/fig_6_2h2.png) |
