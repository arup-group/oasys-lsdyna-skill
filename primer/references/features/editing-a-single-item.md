####  Editing a Single Item

| In any scalar (single item) editing panel you can use the Text Edit button to generate a mini-keyword deck containing just this keyword. It is generated from the scratch data currently populating the editing panel, and will contain any comments embedded in the card. (It is also possible to edit multiple items using Text edit on the keyword editor, this is described in [Editing Multiple Items Using the Keyword Editor](editing-multiple-items-using-the-keyword-editor.md#te_multiple))<br>
<br>Note also that there is a general Text Edit button in the Tools panel that can be used to edit any keyword, not just one in an editing panel or the keyword editor. This is described in [Text Edit](text-edit-external-editing-of-any-keyword.md)<br>

| Rules for using the text editor  <br>The text editor operates as follows:<br> <ul> <li>A temporary filename containing the keyword output is generated in the directory containing the model. If this cannot be opened, for example because that directory is read-only, then the file is created in a temporary directory instead. <br> <br> </li> <li>The relevant editor is launched to read this file. This is done in a separate thread so that the editor process is autonomous and does not &quot;lock&quot; the <!-- #BeginLibraryItem &quot;/Library/primer.lbi&quot; -->PRIMER <!-- #EndLibraryItem -->session in any way. <br> <br> </li> <li>You are free to modify the temporary file in any way you please, or to read new content into it to replace the existing. You can also save copies of the file under different names, and generally do anything you would normally do in an editing session, including aborting the session without changing anything. <br> <br> </li> <li>When you finally exit from the editor the following happens: <br> <br> <ul> <li>Any files other than the temporary file that you might have created (by &quot;Save as...&quot;) are left unchanged on disk, and are not considered or read in any way. <br> <br> </li> <li>If the original temporary file is unchanged - specifically if its &quot;last modified&quot; time has not changed since its creation - then no further action is taken and it is deleted. <br> <br> </li> <li>If the original temporary file has changed then it is read back into <!-- #BeginLibraryItem &quot;/Library/primer.lbi&quot; -->PRIMER <!-- #EndLibraryItem -->via a &quot;mini keyword read&quot; process, and the contents of the file will overwrite the scratch definition in the editing panel. The temporary file is then deleted. <br> <br>Inside <!-- #BeginLibraryItem &quot;/Library/primer.lbi&quot; -->PRIMER <!-- #EndLibraryItem -->this is done by reading all the file contents into a scratch model, then extracting the first definition of the relevant type (here *PART) from that scratch model and using it to replace the definition being edited. So if you import more than a single definition, or perhaps load different keywords from some other file, all except the first definition encountered of the relevant keyword will be ignored. If there are no keywords of the relevant type (here *PART) in the file, then <!-- #BeginLibraryItem &quot;/Library/primer.lbi&quot; -->PRIMER <!-- #EndLibraryItem -->will issue a warning message, the file contents will be discarded and no changes will be made to the definition currently being edited. <br> <br>Therefore you can use this method as an alternative way to update keywords, perhaps by cutting and pasting text in the editor from other files. However it is restricted to changing only the current keyword definition, and cannot be used as a generalised method of importing unrelated keywords into the model. <br> <br>If you want to read &quot;fragments&quot; of some other deck into this model it is better to use <span class="buttontext"> <a href="model-read.md#32MODELREAD">Model Read</a>&#160;</span>to read these into a separate model, then <span class="buttontext"> <a href="model-merge.md#merge">Model Merge</a>&#160;</span>to merge them into this model. This will permit input of any keywords, and the merge operation will protect you against label clashes. </li> </ul> </li> </ul> |
