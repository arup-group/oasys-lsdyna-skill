#####  Mixing Small, I10 and Large Format Files within a Model

Ansys LS-DYNA permits a model to be made up of master and include files using a mixture of small, i10 and large formats, but the syntax and rules are not totally intuitive.

| Ansys LS-DYNA rules for reading decks with files in mixed formats. | Ansys LS-DYNA rules for reading decks with files in mixed formats. |
| --- | --- |
| Rule 1 | The format of the master deck is the "default format" for the whole model, including all include files. It is presumed that all include files will be in the same format as the master file unless one of the suffices defined under "rule 2" is used. <ul> <li> <!-- #BeginLibraryItem &quot;/Library/primer.lbi&quot; -->PRIMER <!-- #EndLibraryItem -->obeys the same rule by default, however unlike&#160;Ansys LS-DYNA it inspects any &quot;long=..&quot; or &quot;i10=..&quot; suffix on the *KEYWORD line of an include file, allowing this to supersede any inherited format. </li> <li> <!-- #BeginLibraryItem &quot;/Library/primer.lbi&quot; -->PRIMER <!-- #EndLibraryItem -->also writes &quot;long=y&quot; or &quot;i10=y&quot; suffices on the *KEYWORD card of child include files unconditionally if their format is Large or I10. </li> <li>If the child is Small format but the parent file is not <!-- #BeginLibraryItem &quot;/Library/primer.lbi&quot; -->PRIMER <!-- #EndLibraryItem -->will add a &quot;long=s&quot; suffix to the *KEYWORD card in the child file to reinforce the point </li> </ul> |
| Rule 2 | If an include file is in a format other than this "default format" then its \*INCLUDE statement must have one of the following suffices: <br><br>| % | Include file is in I10 format |<br>| --- | --- |<br>| + | Include file is in Large format |<br>| - | Include file is in Small format |<br><br> <br>***This is true even if the \*KEYWORD card in the child include file has a "long=xx" or "i10=xx" suffix.***   <br>  ***Ansys LS-DYNA ignores any such suffix in include files, making the \*INCLUDE suffix mandatory.***<br> <ul> <li> <!-- #BeginLibraryItem &quot;/Library/primer.lbi&quot; -->PRIMER <!-- #EndLibraryItem -->does not ignore suffices on *KEYWORD in include files. If they are found they dictate the format of the file </li> </ul> |
| Rule 3 | If an \*INCLUDE card has a "%", "+" or "-" suffix then all the data on that card must be written in that format. <br><br>For example if a parent file is in large format and a transformed child is in small format the correct syntax in the parent is <br><br> \*INCLUDE\_TRANSFORM -  <br> *Small format filename Offsets etc in 8I10 format Further data in 10 wide fields*  <br><br>This is consistent with the rule that using these suffices on a \*keyword alters the format of data on that keyword, but it is not immediately obvious that a parent keyword requiring this suffix to read a child include file in a different format must also format its "own" data in the format of the child. |

PRIMER has "Keep existing" and "Automatic" format modes which can potentially lead to different files being written in different formats. If this occurs it will generate output decks obeying the rules above.
