##### Format: Setting the File Format

| By default the Ansys LS-DYNA output mode is "Keep existing", meaning that each master and include file in a model is written out in the format in which it was read. However PRIMER supports the following options:<br><br><br>| **Small format** | The default Ansys LS-DYNA output format in which numerical data fields are a mixture of 8, 10 and 16 wide. |<br>| --- | --- |<br>| **I10 Format** | Specified by adding " i10=y " to the \*KEYWORD card <ul> <li>The same as &quot;small&quot; format except that data fields &lt;10 wide become 10 wide </li> <li>Lines of 10 data fields may be 10 x 10 = 100 characters long </li> </ul> |<br>| **Large format** | Specified by adding " long=y " to the \*KEYWORD card <ul> <li>Data fields &lt;20 wide become 20 wide </li> <li>Lines of 8 data fields may be 8 x 20 = 160 characters long </li> <li>Lines of 10 data fields may be 10 x 20 = 200 characters long </li> <li>Filenames, pathnames and parameter expressions using an [A80] data field can be 160 characters long </li> </ul> |<br>| **Keep existing** | The format of output files is the same as that when they were read in, these settings are applied on a per include file basis. See also [Promotion to I10 and Large formats](automatic-promotion-to-i10-and-large-formats.md#promotion). |<br>| **Automatic** | Files default to the smallest possible format that will contain their contents, based on inspecting the largest label size in the model. See also [Promotion to I10 and Large formats](automatic-promotion-to-i10-and-large-formats.md#promotion). |<br>| **Binary** | Proprietary binary format. About 1/3 of the size of the equivalent ascii file, and much faster to write. These files are given the extension ".kby".<br> <br>This format is described in detail under the [Compression tab section](write-binary-format.md#write_binary).<br> <br>***Ansys LS-DYNA cannot not read this binary format directly.***  Do not use it if the output is destined for immediate analysis. | | ![](../Storage/primer-22-1/primer_links/sect_3/images/fig_3_3_2a.png) |
| --- | --- |

With the advent of "i10" format the magnitude of labels is now split into three bands:

| Small format | \*PART, \*NODE and \*ELEMENT labels must be in the range 1 to 99,999,999 <br> <br>10 wide fields in other contexts permit larger labels, but generally the three above dominate. |
| --- | --- |
| i10 format | All labels can lie in the range 1 to 9,999,999,999. <br> <br>However the limit of a single precision signed 32 bit integer is 2,147,483,647 so if single precision Ansys LS-DYNA is to be used, or - more importantly - 32 bit binary output files are to be written then it is best to keep labels inside this limit. PRIMER can impose this as a "soft" label limit, see [Setting the current label limits in PRIMER](long-keyword-format-and-large-labels.md#set_label_limit)for more information. |
| Large format | All labels can lie in the range 1 to 999,999,999,999,999.<br> <br>The theoretical limit is higher than this, but it is recommended that this limit of "15 9s" be used. The reasons behind this are discussed in detail in [Setting the current label limits in PRIMER](long-keyword-format-and-large-labels.md#set_label_limit) |

In "automatic" mode the smallest of the three options above that will contain the data is chosen. However if a format that is too small is explicitly chosen in this situation then it will be used until a card containing "i10" or "long" labels is encountered, in which case a new keyword header using the "%" suffix for i10 or the "+" suffix for large will be written and the rest of that particular keyword will be written in teh relevant format.
